# 论文阅读笔记

依据用户提供的论文，生成适合后续复盘、模型设计参考和汇报的中文 Markdown 阅读笔记。保留英文模块名并解释中文含义；以模型方法为重点，实验部分限于消融及直接相关证据。

## 阅读规范

详细规则和示例在 [阅读笔记写作规范](references/writing-guide.md)。该文件保留用户提供的原始规范；按任务需要分节读取：

- 整理内容前，读取“适用场景”“总体写作原则”“开头论文信息块”及四个正文部分的规则。
- 排版与交付前，读取“Obsidian 公式格式要求”“Obsidian Markdown 紧凑排版规则”“Obsidian Markdown 渲染边界规则”“最终交付方式建议”和“Obsidian 公式渲染防错强约束”。
- 编写个人理解时，读取“Obsidian 可读性标记与写作风格”和“模型流程说明中的 Callout 嵌入规则”。
- 末尾的可复用提示词属于使用示例，不需要重复输出，也不作为新增章节。

本入口明确下面的执行方式与格式边界；原始规范中重复或有歧义的写法以这些说明为准。POI、trip、region 等例子只是写作示意，不能套成当前论文事实。

## 笔记结构与内容

先放紧凑的论文信息列表，然后正文使用以下四个一级标题，不增加其他一级章节：

```markdown
# 0. 实验
# 1. 论文核心问题
# 2. 论文贡献
# 3. 模型流程说明
```

1. **实验**：介绍消融变体去掉或替换什么、结果及其解释、值得注意的地方。不展开主实验、完整 baseline 比较、超参数或效率实验。无严格消融时如实说明，仅概括与模块有效性直接相关的证据。
2. **论文核心问题**：综合摘要、引言和方法开头说明现有方法不足、作者的核心矛盾和建模出发点，回答为什么要做。
3. **论文贡献**：主要翻译整理引言中的 contribution，保留作者的含义，不将个人判断写成作者声称的贡献。
4. **模型流程说明**：先总览，再按实际模块讲清输入与任务、特征来源和嵌入、关键操作与中间输出、模块连接、预测与融合、损失及监督信号，最后综合理解。原规范的 3.1–3.8 是组织参考，模块数量和小节按实际论文调整。

模型说明展开到计算过程可理解为止，不写代码级流水账。解释公式作用、每个关键符号及其结果用于哪里；有候选相关计算、目标信息使用、负样本构造或训练与推理差异时，在对应步骤说明。

事实以所给论文为依据，保留必要的章节、公式或图号锚点。消融数值、公式和设定必须来自原文；原文未交代的细节局部注明。不把个人理解写成论文事实，不把有限消融当成机制因果证明。复现风险和迁移启发需要结合当前论文具体证据；用户未提供研究方向时，不编造“我的模型”或研究背景。

## 发表信息与代码状态

按参考规范的期刊、会议或预印本模板核验论文信息，来源链接附在对应字段后，并记录查询日期。期刊填写正式名称、发表时间、JCR 分区及学科类别、中科院分区及版本、JIF 及数据年份；会议填写正式名称、年份与轨道、CCF 目录等级及版本。顶会认定需要独立依据，Workshop 不自动沿用主会等级。

联网优先查看出版社、会议记录、指标发布机构、CCF 官方目录及作者官方项目和仓库。默认使用最新可核实的指标版本，用户指定年份则按指定年份；指标年份、发布年份、发表年份与查询日期分别记录。官方数据不可访问而使用公开转引时注明来源和转引性质；无法核实的项写“未核实”，不猜测。

代码公开状态保持参考规范的带条件表述：找到与论文对应、包含实现的作者官方仓库时提供链接；完整检索后仍未发现时可写“否（截至查询日期未发现作者公开代码）”，保留检索范围与日期限定；访问失败、承诺发布、第三方复现、仅有数据或权重、部分实现和许可证缺失分别说明。无法完成检索时写“未核实”，不写确定的“否”。

## Obsidian 排版

- 默认直接生成 UTF-8 `.md` 文件。优先遵循用户指定的文件名和输出目录；未指定时保留输入文件主名，输出至论文目录的 `阅读笔记/` 子目录，不改动输入论文。更新现有笔记先读取并保留用户手写内容。
- 行内数学用 `$...$`，独立数学用 `$$...$$`；两个 `$$` 各自单独占一行，前后留空行。不使用 `\(...\)` 或 `\[...\]`，不把要渲染的公式放入代码块。
- 数学环境内只写 LaTeX，不混入 Markdown 标题、列表、引用或普通解释性正文。原规范对 `-`、`+`、`*`、`>` 的禁用指 Markdown 控制标记；合法的数学减号、加号、乘法、比较符号与 LaTeX 命令应正常保留。
- 同一列表内部采用紧凑排版；标题、自然段、列表结束、引用结束和公式块之间保留必要空行。加粗、斜体、高亮用于实际重点，不跨数学或其他块级边界。
- 用普通正文说明原文方法，引用块或“个人理解”标注解释性判断；callout 优先靠近具体模块、公式或疑问。通常全篇 3–6 个，复杂模型可适度增至 6–8 个，不为凑数量添加风险或结论。复杂块级公式放在 callout 外。
- 默认在聊天中只返回文件链接和简短说明。用户明确要求完整原始 Markdown 时，可用代码围栏交付；内部含代码围栏时，外层使用更长的围栏避免提前闭合。常规笔记文件内部不包裹整篇代码块。

## 交付检查

核对四部分结构、发表信息的年份与来源、消融数据和关键运算，并确认论文事实与个人理解可区分。检查 `$`/`$$` 配对、独立公式的空行、引用及 callout 边界、强调符号和模板占位项；不能把正常 LaTeX 运算符误判为 Markdown 列表符号。

可访问 Obsidian 时抽查实际渲染；仅做源码检查时如实说明检查范围。返回生成笔记的可点击链接，避免重复粘贴长篇正文。本 skill 可独立使用，不要求安装其他研究 skills，也不自动扩展为审稿、代码复现或研究 idea 工作流。
